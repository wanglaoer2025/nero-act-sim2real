## run17 最终闭环结果与图形停点核查

run17 已完成20/20轮，验证集选择第15轮，验证L1为0.0033821791401139013。开发回归16项和新独立16项均已完成，均为 **0/16** 完整抓放成功；32项均未触发GRASP或CARRY事件。此前“等待评估”状态已结束。训练输入和代码修复通过，不代表策略行为修复。

图形界面默认显示开发名义场景 `cup_+0_+0` 的失败记录。用户观察到“到杯旁但未抬起搬运”与记录一致；实际上它还未夹稳：双指接触为false，开口约95.04mm，杯子由桌面支撑，抬升量为0。

对初始完整物理快照和全部提交动作重新执行精确重建，机器人状态逐点误差为0，最终杯位置与原结果一致。首次非预期接触位于第1663控制步、第20微步（仿真时刻83.192秒），接触体是 `cup` 与 `gripper_base`，而非两指正常夹持。该时刻附近末态夹持中心水平偏差13.62mm、高于目标抓取高度24.91mm，link7相对教师目标旋转误差12.87°。末次ACT原始动作块的开口从92.67mm逐步减至84.88mm，说明已有提前闭爪预测；抓取深度尚未满足，执行器按原保护保持张开。不能将这一保护直接删除来把闭爪当作成功。

这证明名义场景在接近、下降对中阶段已偏离，不能只归因于“缺少抬升动作”。它不证明32项失败均有同一原因。分类为：开发组8项非预期接触、6项预算耗尽、2项原始预测越限；独立组分别8、7、1项。

证据：[停点精确重建诊断](../nero_act_gui_inspection_20261018/run17_stop_diagnosis.json)、[GUI操作说明](../nero_act_gui_inspection_20261018/README.md)。GUI按N可查看run15历史完整成功开发场景，但不得将它作为run17或独立评估成功。
