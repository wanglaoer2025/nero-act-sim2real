# NERO 项目 Agent 接手说明

本文是新编码 Agent 的第一入口。它只记录项目地图、当前事实和不可违反的边界；用户运行命令见 `README.md`，细节按 `docs/README.md` 导航。

## 接手后的前十分钟

1. 读取 `README.md`、`docs/README.md` 和本文件。
2. 运行 `git status --short`；当前仓库经常包含未提交实验代码和本地数据，不能覆盖、回退或删除不属于本次任务的改动。
3. 根据任务只读取相关模块和文档。出错时先查 `docs/robot-troubleshooting.md`，不要重复已经失败过的修补方法。
4. 从项目根目录运行模块；当前机器的 Python 环境是 `source /home/user/nero/bin/activate`。
5. 默认先做离线测试或 `--dry-run`。除非用户明确要求实机运动，否则不要发送运动、夹爪、失能、复位或急停命令。

## 项目是什么

这是 NERO 七轴机械臂的 Python 项目，组合了：

- `pyAgxArm` + SocketCAN `can0` 的关节、笛卡尔和夹爪控制；
- 固定 ZED 相机的 RGB-D、手眼标定和 TCP 标定；
- YOLO 检测、三维定位、抓取放置和透明器皿倾倒实验；
- 中文离线语音识别到受限抓取指令；
- ACT 模仿学习的数据采集、回放、训练、离线评估和实机安全推理。

现场已知配置：NERO 固件 `V120`，CAN 默认 `can0 @ 1 Mbps`，ZED 倒装后统一旋转 180°。SDK 运动接口使用米和弧度；用户配置通常使用毫米和度。

## 代码地图

| 位置 | 唯一职责 | 放置规则 |
| --- | --- | --- |
| `src/arm/` | 机械臂使能、失能、准备、复位和夹爪 CLI | 只放操作员会直接运行的命令 |
| `src/calibration/` | camera→base、手眼和 TCP 标定 | 标定入口和专用编排不得散回 `src/` 根目录 |
| `src/demo/` | 已完成、可独立运行的能力演示和基线流程 | 新实现用 `snake_case.py`；文件头写用法与硬件风险 |
| `src/<case_name>.py` | 尚未完成验收的案例流程 | 验收完成后再移入 `src/demo/` |
| `src/act/` | ACT 数据、模型、训练、回放和实机适配 | ACT 专用代码不得散回 `src/` 根目录 |
| `src/utils/` | 机械臂、倾倒、视觉和语音公共辅助模块 | 没有 `main()`、仅被其他流程调用的公共逻辑放这里 |
| `src/voice/` | 语音识别和抓取可运行入口 | 白名单解析放 `src/utils/voice.py` |
| `scripts/` | 系统/CAN/固件及离线维护工具 | 不作为可导入业务库 |
| `config/` | 当前现场标定与运行 JSON | 提交 `.example.json`，真实标定值默认留在本机 |
| `configs/` | 可复现实验 YAML | 文件名包含任务或实验变体，路径使用仓库相对路径 |
| `tests/` | 默认不连接硬件的回归测试 | 与被改模块同次更新 |
| `docs/` | 设计、操作、故障和实验记录 | 先在 `docs/README.md` 登记职责 |
| `data/`, `logs/`, `artifacts/`, `checkpoints/` | HDF5、日志、图表、模型 | 本地生成且被 Git 忽略，不放源代码 |
| `third_party/` | 固定来源的外部 ACT 实现 | 不做无关格式化或大范围重写 |

源码、测试、脚本和配置使用 `snake_case`，Markdown 文档使用 `kebab-case`；固定入口文件等例外及完整规则见 `CONTRIBUTING.md`。禁止为同一功能长期保留两套不同命名。

## 稳定接口和数据约定

- 机械臂创建、使能、动作确认、反馈和运动等待统一走 `src/utils/arm.py`。
- 相机坐标、旋转、外参和标定算法位于 `src/utils/vision.py`。
- 夹爪动作使用独立命令；七维 arm qpos 不包含夹爪。ACT 完整 state/action 当前均为八维：七关节加一维夹爪。
- 人工可读关节为 `deg`，SDK 关节为 `rad`；人工笛卡尔位姿为 `mm + deg`，SDK 位姿为 `m + rad`。
- CLI 从仓库根目录以 `python -m src...` 运行。新增入口应提供 `main() -> int` 和 `if __name__ == "__main__"`。
- 普通可恢复失败应停止发送并保持当前位置，同时输出目标、反馈、控制器状态和误差；不要把普通失败自动升级成电子急停。用户 `Ctrl-C` 和明确严重故障仍按具体入口的安全策略处理。

## 实机安全边界

- 同一时刻只能有一个 Python 进程控制 CAN。
- `move_j`、`move_p`、`move_l` 都不是碰撞规划器；终点可达不保证路径安全。
- 新路径按 `dry-run/打印目标 → 空夹爪悬停 → 空物体低速分段 → 完整动作` 验收。
- 运动入口默认不执行，必须显式 `--execute` 并显示操作、风险和大写确认口令。
- 失能、Leader 模式或断电可能使机械臂下落，必须提醒操作者扶稳机械臂。
- 不通过放宽工作区、关节限位、示教范围或关闭反馈检查来掩盖错误。

## 完成一次修改的最低要求

1. 复用已有公共函数，避免产生第二套连接、单位转换或确认流程。
2. 修改公共接口前搜索全部调用者；保持已公开 CLI 兼容，或在交付中明确迁移方式。
3. 非硬件逻辑至少运行相关 `unittest`；不得把需要真机的动作伪装成自动测试。
4. 新命令先验证 `--help` 或 dry-run，文档只写实际存在且已验证到对应安全阶段的命令。
5. 更新 `docs/README.md` 的入口或状态；新故障及根因写入 troubleshooting，不把调试流水账堆进 README。

更完整的文件、API、测试和提交规范见 `CONTRIBUTING.md`。
