# Nero 仿真 ACT → 真机：连续空中动作测试

本包包含**重新训练的 ACT 权重、配套归一化统计、完整源码和连续闭环执行器**。目的：验证仿真学到的动作能够驱动真实机械臂与夹爪。不是原有杯子抓取策略的完整迁移，也不声称能够抓起杯子。

模型以最近回传的真机姿态为训练起点，在 MuJoCo 中学习约 13 秒的多关节空中动作：J1 约 +2.29°、J3 约 +1.43°，其余关节小幅配合；夹爪总开口约 60→68→60 mm。执行时持续读取实际反馈和实时相机，由 ACT 反复预测动作块；不是回放示教、固定 J1 指令或把旧模型的大动作缩小。

## 现场运行

保留已经验证的 ROS 驱动、桥接与 MoveIt 启动方式；驱动为唯一 CAN 控制方，不要同时启动 SDK 控制程序。默认 ROS Jazzy、工作区 `/home/user/projects/nero_ros2_ws`、ROS_DOMAIN_ID=42。机械臂空夹爪悬停，确认整个小幅运动范围没有障碍，实体急停可用。驱动应已使能、速度比例在 (0,5]，arm/gripper 控制器 active。4090 的控制桥在空闲时关闭硬件命令转发，驱动启动参数 `control_enabled=false`；该参数不是实时门状态。现场副本要求驱动只订阅 gated 话题，并在同步动作执行时由现有控制桥开门。入口不会替你启动驱动或修改这些参数。

```bash
cd /home/user/wq/nero_aligned_air_sequence_20261016_onsite
export ROS_DOMAIN_ID=42
bash run.sh --execute
```

核对终端预览后，按提示输入大写 `ACT_AIR`。默认执行 **18 秒**，包含完整动作与末端观察时间。模型 Python 默认 `/home/user/nero/bin/python`；如果环境位置不同，使用 `bash run.sh --execute --policy-python /实际路径/bin/python`。ROS 环境路径可通过 `NERO_ROS_SETUP`、`NERO_WS_SETUP` 指定。

起点必须接近 `latest_reported_state.json`：每轴误差 ≤0.005 rad，夹爪误差 ≤4 mm。超出则停止，不自动回位、不重定位模型。完成后机械臂处于新的末端姿态；再次运行前，按现场已有安全操作恢复已知起点，不要直接重复执行或放宽阈值。

`bash run.sh` 仅检查随包保存的旧图像/状态对应的 100 步预测，不发运动，也不代表现场已就绪。`--execute` 才使用当前相机和反馈，并在确认后重新取观测，避免复用确认前的预测。

## 验收和本地排错

每次运行写入 `logs/act_*/report.json`，并保存观测、图像、原始预测、实际下发目标、控制器结果与真实反馈。完整运行必须满足实际 J1 位移、末端误差、夹爪开口变化等判据，才报告成功；静止反馈不会被当作成功。按终端输出检查 `success`、`sequence_completed` 和错误原因即可，无需再回传文件才能判断这一轮结果。

若未发送运动，按本地错误检查：起点是否匹配、ROS domain/驱动是否在线、桥接状态是否与实际反馈同步、两个控制器是否 active、模型环境能否导入 Torch 与 ZED、相机是否被其他程序占用。不要通过改限位或改模型许可字段绕过失败。执行目标为 20 Hz 轨迹点、约 2 Hz 推理更新，真实服务耗时和更新频率会记录；过期预测或反馈、目标拒绝、跟随失败会中止。取消 ROS 目标不等于保证底层 CAN 最后目标已停止，异常运动使用现场实体急停。程序不自动失能、不自动回位。

## 4090 现场副本的时序修复

原包和权重保留不变。现场副本补齐了七轴、单夹爪、机械臂与夹爪同时执行时的八维 gated 消息校验，修复 ROS 初次发现等待和 ZED 原生日志混入 JSON 通道的问题。

后续推理采样安排在每个 0.5 秒动作块的约 0.4 秒处，减少下一块发送时的观测年龄；动作客户端在第一次执行用观测之前完成初始化。发送前 250 ms、块内预测 750 ms、动作包络和夹爪范围保持不变。`report.json` 中的 `block_attempts` 记录每次校验及其观测年龄，即使失败也保留；`timing` 保留实际块频率和运行时长，`inference_timing.json` 与 `policy_predictions.json` 保存采样、请求、结果接收及推理耗时。

一次无运动的现场计时预检测得推理往返约 33.9 ms、状态校验约 12.6 ms、校验后观测年龄约 54.8 ms。历史 11:45 运行完成了 13 个动作块后被时效检查中止；修复后的 12:07 实验见下文。已经生成的回位规划仅供复核；实际执行前须重新读取起点并重新规划，不能直接发送旧 JSON。

## 恢复到本轮模型的准确起点

普通复位程序可能回到旧起点，例如 J3 约 0.100 rad；本轮训练起点 J3 约 0.10992 rad。不能将它们视为相同姿态，ACT 的 0.005 rad 起点门槛保持不变。手动或 SDK 复位后，虚拟控制器也可能仍停在旧终点；必须先在硬件输出隔离的条件下将虚拟状态同步到真实反馈，不能直接打开控制门追踪旧终点。现场 12:01 已完成一次这样的虚拟同步，CAN TX 计数没有增加。

新增独立恢复入口，默认仅按当前反馈重新规划并检查路径，不发送动作：

```bash
bash run.sh --return-to-start
```

确认现场回程通道及急停可用后，显式执行并输入 `RETURN_START`：

```bash
bash run.sh --return-to-start --execute
```

此入口只恢复七轴到 `model/runtime_metadata.json` 中的准确训练起点，夹爪保持当前开口，成功须有真实反馈到位。它是独立的 MoveIt 恢复操作，不是 ACT 推理；不自动衔接 ACT，不自动处理夹爪偏差，单轴距离超过 0.05 rad 会拒绝。恢复完成后再运行 ACT，按提示输入 `ACT_AIR`。

需要准确执行 200 步时使用：

```bash
bash run.sh --return-to-start --execute
# 现场输入 RETURN_START，成功后继续：
bash run.sh --execute --steps 200
# 现场输入 ACT_AIR
```

`--steps 200` 为 20 块、每块 10 个 20 Hz 轨迹点，机械臂和夹爪同时执行，不将两组相加计数；名义轨迹时长 10 秒，实际墙钟时间含校验与动作服务开销。只有两组动作均成功且真实反馈检查通过，才计入 `completed_step_count`。`submitted_step_count`、`completed_step_count`、`step_target_completed` 记录精确计数；未完成不能报告成功。200 步只验收这段动作，`sequence_completion_checked=false`，不据此声称约 13 秒训练序列的完整末端验收。

原有范围、起点、碰撞、反馈和预测时效门槛保持不变。步数需为 10 的整数倍，最多 400，仍受 20 秒墙钟安全上限限制；服务开销可能使较大步数因超时中止。`--steps` 与 `--seconds` 不能同时使用；未指定时仍默认 18 秒。

68 项本机离线回归通过。第一次准确 200 步真机尝试见 `logs/act_20261016_121413_533140256/report.json`：6 块、60 步实际完成，第 7 块校验耗时约 101 ms，使观测年龄达到 253.6 ms，被原有 250 ms 门槛拒绝，未发送该块。`success=false`、`step_target_completed=false`，不可据此声称 200 步通过。详细重算见同目录 `independent_200_step_review.json`。中止后的只读检查显示 ROS 同步正常、真实反馈稳定，但机械臂处于中间姿态、夹爪约 66.43 mm；下一轮必须恢复并检查七轴与夹爪起点，不可直接续发剩余 140 步。校验阶段内部各服务耗时尚未逐项记录，101 ms 延迟的底层原因未唯一确定。
