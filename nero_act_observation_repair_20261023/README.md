## 1. 这次确认的问题

| 问题 | 本轮证据 | 结论的边界 |
|---|---|---|
| 只修杯位不足以修好策略 | 固定模型、图像、反馈、蓝卡与全部保护，只替换匹配曝光的杯位三项；5个场景完整流程0/5 | 说明旧策略与原有有偏观测存在耦合；不能据此断言视觉不重要或这是唯一原因 |
| 夹稳到抬升的监督近似冲突 | 8条训练示教中7条出现工程分辨率下近似相同输入、不同首点关节目标 | 是可观测性风险，不是数学上完全相同输入的证明 |

本工程沿用的“杯底中心”评估参考是杯body中心减去基座竖直方向半杯高，适用于当前近直立场景；它不是任意倾斜杯的独立底面测量。原七个场景已经全部用于开发，不能再次称为独立验收。

## 3. RGB-D候选修复

当前候选`rgbd_observer_v2.py`使用1280×720 RGB、同曝光的米制相机Z深度或SDK光学XYZ、置信度，联合拟合有限空心杯的表面和可见轮廓，允许小幅倾斜。ACT RGB仍为320×180，15维接口和20×8动作输出不变。原`rgbd_observer.py`保留为封存v1；独立复核发现其有符号残差质量门槛漏洞，v2已改为绝对残差并通过异常点拒绝测试。

关键修正是沿相机射线取**第一个可见表面交点**。仅寻找最近杯壁会把外壁与不可见内壁混淆，遮挡测试最初误差2.91毫米；加入可见性约束后同一测试通过，未放宽2毫米门槛。没有物体真值输入、历史杯位缓存或缺失深度的RGB高度兜底。低置信度/非有限深度、不可观测或多只完整黄色物体显式拒绝。

| 帧级检查 | 有效帧 | 有效帧最大误差 | 判定 |
|---|---:|---:|---|
| 理想渲染深度，开发帧 | 14/14 | 1.900毫米 | 通过 |
| 理想渲染深度，留出观察器帧 | 21/22 | 1.595毫米 | 通过 |
| 预设噪声，开发帧 | 12/14 | 0.910毫米 | **未通过：有效率85.7%** |
| 预设噪声，留出观察器帧 | 21/22 | 1.543毫米 | 通过 |

判据为有效率≥90%，所有有效帧误差≤2毫米。无效帧仍计入分母；不存在按真值选择输出。v2新增拒绝9005/query593压力帧，其绝对深度残差95分位2.191毫米超过原2毫米门槛；不降低门槛或删除该帧，故最终`mechanism_passed=false`。v1原先整体通过的结论不再作为当前依据。

预设噪声是相机Z标准差0.35毫米、随机缺失15%的合成压力测试，**没有证明它覆盖实景深度分布**。留出观察器帧来自已用于策略开发的场景，不能算完整策略的独立验收。

v2候选95分位耗时约430～891毫秒，尚不满足实时闭环要求，`real_time_latency_qualified=false`。拟合雅可比推算的标准差也不是实测误差上界。真实杯把、杯口、标定与名义尺寸误差仍未验收，正常策略尚未切换到这个观察器。

## 4. 相机只读结果

ZED2i，序列号39602891，SDK5.4.1，HD720/30Hz。NEURAL_LIGHT使用本机已有模型，保存20张严格递增的新曝光，约29.96fps。像素数组旋转180度，SDK XYZ向量仍保留原光学坐标；未进行第二次轴翻转，数值测试覆盖此约定。

旧20帧报告的静止判定仅检查ROI中心，复核证明它会漏掉轴向移动；其0.163825毫米统计保留为历史记录，不能据此证明场景静止。`depth_quality_v2.py`新增共享像素XYZ变化检查，名义1毫米稳定性门槛，仍明确`stationary_scene_verified=false`。保留3帧复算共享9753像素、位移指标0.574毫米、Z标准差95分位0.228640毫米；原20帧只保存3帧原始数组，未独立复算全部20帧。

未来采集入口改为`capture_depth_quality_v2.py`，本轮仅检查帮助入口，未重新打开相机。相机/机器人时钟同步、绝对几何精度和TCP独立验收均未通过。对保存的0、9、19帧应用完整v2 RGB-D前端，3帧仍在蓝卡检查处被拒绝，不能把“有稳定深度”写成“当前真机视觉输入已就绪”。

## 5. 下一步的限定修正

1. 修复9005/query593压力帧的表面拟合稳健性、当前蓝卡的朝向支持和拟合时延；使用已保存数据，保留尺寸、可见边界、无缓存和误检拒绝检查。当前机制未整体通过，不开新训练，也不要求现场重复拍板或测量。
2. 修正离线专家示教的固定等待：现有close/release各固定8秒，末尾稳定输入与下一帧抬升目标近似冲突。拟改为原物理接触合同满足且稳定后结束close、落桌支撑且释放成立后结束release，原8秒作为截止期限；不是把闭爪改成0.5秒，也不往在线ACT输入中加入阶段真值或人工动作。
3. 先验证新示教物理完整性、首动作监督与接近保持，再用统一前端重建训练/评估输入。加入当前相机下原模型成功接近的保持数据；不把失败ACT动作当专家标签，不混用旧观察器的有偏特征。
4. 机制与数据通过后才进入小预算训练对照，随后重新封存未用于修复的完整场景。完整仿真、当前实景只读链路和原保护均通过后，再准备真机动作。

上述是后续工作要求，本轮未增加优化预算，未声称已经实现示教切换或完成重新训练。
