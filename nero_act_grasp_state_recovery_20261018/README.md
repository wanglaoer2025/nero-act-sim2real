第一批原计划6条；验证场景41未到预设采样高度，按原阈值拒绝并保留失败记录，不合成快照。修订批次保留已通过物理/重放检查的原场景2条训练样本，增加场景42的2条验证样本，共4条、2个来源组。原66条数据保留，总70条（训练50、验证20），新增样本是局部恢复片段，不算独立完整示教。

## 本轮实际结果与下一步讨论

run20完成声明的3轮训练，275个受保护输入通过完整性检查；按验证总损失选第2轮。第2轮和第3轮最终模型均在原场景出现异常接触停止，实际抬升0、搬运0，没有GRASP事件。因此不扩展独立16场景，不部署，也不以run19验证42的成功替代本场景。

下降恢复数据、姿态训练损失、低位恢复数据三种修正均未让原场景完成。需要重新审视训练/推理方案，不继续仅加轮数或放宽保护。

只读架构审计确认：`FullTaskPolicy.forward`虽然接收动作标签，但调用不带标签的模型路径，训练和推理都使用零潜变量；KL权重0。31个后验相关参数张量在本轮前后完全相同，其他73个张量变化。这是历史README已明确记录的prior-only设计，不是新发现的意外代码错误，也不能断言它就是本次失败原因。

建议下一版评估恢复ACT的条件CVAE训练路径：未来20点动作只在训练时进入后验，加入明确的KL约束；推理仍只接收当前图像、9维因果观测，用零潜变量输出20×8动作。先验证后验梯度及无标签推理，再以零潜变量的完整闭环评估选候选。需要先讨论这一训练方式调整；恢复CVAE不保证一定成功。原模型、数据、保护及失败证据均保持。
