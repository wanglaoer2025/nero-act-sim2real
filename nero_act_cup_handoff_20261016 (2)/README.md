# 4090 → 仿真电脑：黄色杯 ACT 抓放任务回传包

先读取 `simulation_request.json` 和 `return_requirements.json`，再看 `scene/current_capture/camera_0_upright_rgb.png`。目标是继续 **ACT sim2real 抓杯**，下一轮真机先验收接近杯子的非接触预抓取段。

## 在仿真电脑上检查包

```bash
tar -xzf nero_act_cup_handoff_20261016.tar.gz
cd nero_act_cup_handoff_20261016
python3 verify_bundle.py --check-capture
```

校验仅读取文件，不加载模型、不连接 ROS/CAN/相机。完整性检查只需 Python 标准库；加 `--check-capture` 时需要 NumPy。验证通过不代表抓杯策略已通过。

## 当前事实

- 4090 已完成 ACT 空中动作实测：30 块、300 步全部完成，实际 16.522 秒，末端最大关节误差 0.001079 rad。机械臂停在该序列末端；包内采集的是随后静止场景。此结果只证明空中控制链可用。
- 当前真实采集为 101 组 RGB/七轴/夹爪记录，约 19.86 Hz。图像 640×360、RGB、已旋转 180°；模型预处理目标为 90×160，不能再旋转一次。配对依据主机接收时间，不是硬件同步。
- 用首帧及其同一条状态重建仿真起点，详见 `simulation_request.json`。不要用旧 v9 姿态，也不要用空中模型的训练起点替换当前姿态。
- 杯外径 75 mm、高 95 mm、空杯 50 g，目标是黄色杯 → 蓝色卡片。当前视觉估计杯中心约 `[-512.46,-20.85,37.5] mm`，放置杯中心约 `[-514.62,-218.72,37.5] mm`，坐标系为 Nero 基座。这些不是可直接发送给真机的实测目标。
- 桌面暂保留 Z=-10 mm，来自已提供的 10 mm 底座支架与模型基准假设。蓝卡已知尺寸诊断的最佳 PnP 解比该桌面约低 11.1 mm；颜色边缘、实际尺寸边界和外参误差尚未独立区分。不能把诊断值直接覆盖桌高。
- 相机外参使用现有 Oct14 文件，TCP 保留 SDK 法兰 +X 135 mm 手工近似。旧仿真 TCP 经坐标系映射后与此差约 29 mm；接触几何尚未实体验证。原文件和换算说明均已附带，无需再次索要已有标定。

## 仿真端这次应完成什么

1. 用当前配对状态、相机及杯/蓝卡位置对齐正式抓杯仿真，输出真实图与仿真图的对比。基础 MuJoCo 网格仅供参考；沿用另一台电脑已有的正式抓杯采集与评估工程。
2. 核对桌面、TCP 和杯壁/夹爪接触几何，保留未验证项；生成真正接近杯子、张开足够抓住 75 mm 杯子的任务示范。不要重复训练小幅空中摆动。
3. 训练独立的任务 ACT，使用配套统计，明确 8/14/15 维输入中每一项的顺序、单位及初始化。现有现场参考执行器只接受 8 维空中模型，不能直接替换权重接抓杯。
4. 对同一冻结权重做无教师闭环评估，覆盖独立场景、噪声、纠正起点和实际执行延迟，保留失败。不能把历史 300 步空中成功转写成抓杯成功。
5. 按 `return_requirements.json` 一次带回权重、统计、配置、场景对齐、评估轨迹、完整非接触预抓取预览与配套执行器。先准备接近杯子的真机阶段；闭爪和搬运另做实测验收。

执行器需保留本机已验证的控制链及修复：ROS Domain 42、现有 ROS 驱动独占 CAN、现有 control_gate、连续米制夹爪、真实反馈验收、每块 10 个 20 Hz 轨迹点、约 2 Hz 查询、发送前 250 ms/块内 750 ms 时效检查；复用校验服务客户端，每点仍取新结果。严格墙钟 20 Hz 尚未验收，评估应计入实测约 1.81 Hz 动作块频率与服务耗时。

本包不新增真机接近、闭爪或抓杯运动，也未生成新抓杯权重。未通过的验证应在回包中如实标记，不通过放宽阈值或修改许可字段放行。
