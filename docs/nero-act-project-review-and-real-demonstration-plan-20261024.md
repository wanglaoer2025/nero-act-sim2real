# NERO ACT 仿真到真机全过程复盘与真机示教微调方案

汇总截至2026年10月25日，文件名保留10月24日初始版本日期。任务是让NERO七轴机械臂根据当前相机和机器人反馈，将黄色空杯抓起、抬升、搬运到蓝卡、放置、松爪并退出，并在明确的工作区内适应不同杯位。

本报告覆盖本轮对话、2026年10月14日至25日的主要实验，以及9月原项目的数据、运行口径补审；旧模型与当前15维模型分别记录。实验目录中的日期是版本标签，实际执行时间以各日志为准。文中“通过”都注明是软件检查、局部机制、完整仿真、真实只读还是实物动作，避免混用。

## 一 当前结论

可以用真机示教微调ACT，而且当前值得优先补足的是**真实画面、真实动作命令和反馈、真实夹持与释放、多位置及偏离状态恢复的数据**。原ACT工作本身使用真实示教学习，算法没有要求每个新位置都先生成一条仿真轨迹。[ACT原论文](https://arxiv.org/abs/2304.13705)

但是，本项目已有的“真机做过动作”“保存了HDF5”“真实输入能推理”，还不能等同于“有可直接微调当前模型的合格示教”。本次复盘发现，旧真实记录中存在把同帧实测关节直接作为动作标签的情况；它记录了机器人怎么动，却没有按当前模型的合同保存机器人实际收到的关节目标。这需要在使用已有数据前专门审计。

### 1.1 10月25日历史根因核查

用户要求对比历史所有日志查根因。本轮读取工作区1,953份及原NERO仓库429份，共2,382份日志/诊断候选（872份JSON、1,510份文本），对关键训练、执行与验收链追溯原记录，并直接复算68份HDF5、180,934帧的上一命令选择、三个旧夹爪NPZ及最新四个接触拒绝。最强证据指向：**局部监督和完整闭环行为脱节、共享输出更新破坏既有阶段，视觉有效域及接触几何又独立阻挡运行。** 不能把全部问题归为渲染差异、少训闭爪或权重损坏。范围、反例和因果等级见[根因核查全文](../nero_act_root_cause_audit_20261025/README.md)。[S71]

对当前一支68份HDF5的因果选择复算为0次当前/未来命令被当作previous，最大夹爪步长约0.200003毫米；79份旧真实RGB8又没有直接训练1a28。因此不能把已修时序标签或旧真实数据直接当作当前主策略失败原因。CVAE漏训曾存在，但修复后仍有名义完整失败，也不是当前统一解释。[S73]

原仓库173份ACT运行摘要没有完整任务验收字段；137份`status=passed`不能视为137次抓放成功。例如50步、50命令、夹爪事件明确为空、距抓取点仍326.846毫米的一次运行也标为passed。旧14维双RGB使用启动时固定的绝对位置，与当前逐曝光15维输入不同，不能因都叫“位置条件ACT”就把数据和成绩连成一个模型。原始代码、字段口径与反例见[外仓库补审](../nero_act_root_cause_audit_20261025/external_project_acceptance_audit.json)。[S71]

新只读对照固定CPU、1a28与同一15维数值输入，仅换RGB来源：平均每通道差1.085/255，首两点七轴输出最大变化0.000522 rad。它证明RGB变化可以影响动作；归档教师帧并非已证明的历史运行帧，仍不能把3/7→1/7单独归因于CPU或渲染。[S72]

最新四个附着杯拒绝也不同：9000和9201的模型最低杯边继续下降；9005虽然TCP升高，最低杯边仍先下降；9300全扫掠比起始浅，却因28.8纳米局部反向未满足严格单调例外。不能把它们统一认定为真实碰撞或观察器误报，更不能由此取消保护。[S74]

## 二 用户目标是怎样逐步明确的

最初关注MuJoCo、MoveIt和RViz是否具备，以及新文件能否用于验收真机抓取。后续目标逐步收敛为：

1. 先证明真机控制链路能执行，而不是只有虚拟控制器返回成功。
2. 执行与仿真幅度一致的完整动作，不反复只做小角度测试。
3. 最初允许空载和未抓起杯子的迁移演示，随后明确要求真实夹杯、搬运、放置。
4. 明确要求ACT仿真训练迁移，不能把YOLO加MoveIt的成功当作ACT成功。
5. 在线ACT闭爪失败后，接受先用ACT在仿真中生成的完整轨迹做受保护真机回放。
6. 反复杯位对齐、下降碰杯后，进一步要求摄像头在动作过程中实时提供位置反馈，让策略适应不同杯位。
7. 接受15维视觉位置条件ACT、短历史对照和多轮限定微调，但要求异常停止、保留原保护。
8. 提供新手眼标定，希望复用已有记录，减少反复测量。
9. 最近关注微调为什么退化、为何换位不能直接执行，并提出用真机示教增强泛化。

这些目标之间有包含关系。空载链路成功、某个固定位置成功、教师抓放成功，都是中间结果；它们不能替代最终的在线、多位置、完整ACT真机能力。

## 三 必须区分的三条技术路线

### 3.1 视觉加MoveIt教师抓放

相机定位杯子和蓝卡，使用已知尺寸、桌面和TCP模型形成几何目标，再由IK、笛卡尔路径和MoveIt生成动作。它可以完成实际抓放，也可以为ACT提供示教，但现场动作并不是神经网络自主生成。

10月16日的完整实物抓放属于这条路线。现场的GRASP、RELEASE和最后退出确认说明该次物理任务完成，不能据此给ACT部署标志置为通过。[S01] [S07]

### 3.2 在线ACT

```text
当前图像 + 当前关节/夹爪反馈 + 因果命令历史 + 当前几何观测
                         ↓
                   ACT预测动作块
                         ↓
          原始动作检查、限速、碰撞与接触保护
                         ↓
                 执行短前缀，再重新观察
```

这条路线有机会适应杯位变化，因为每次重新查询时都能使用新图像和新位置。实际能否纠偏，取决于定位准确性、输入时间配对、训练覆盖、策略对位置的敏感性和闭环恢复能力。

### 3.3 ACT仿真轨迹回放

```text
冻结ACT在仿真中运行 → 保存实际施加过的目标 → 核对当前现场 → 真机回放
```

回放证明“仿真学出的动作序列能够进入真实控制链路”。回放中的相机可以用于核对和保护，但不等于在线ACT正在依据当前图像重新生成动作。杯子改变位置后，原轨迹不会自动改道；因此历史上反复要求恢复杯位，是固定参考回放的限制，不是ACT算法要求用户永远把杯子摆在一个点。[S10] [S49]

### 3.4 MoveIt、YOLO和ACT各自承担什么

| 组件 | 合理职责 | 不能据此声称的结果 |
|---|---|---|
| MuJoCo | 生成物理示教、训练环境、闭环仿真、接触诊断 | 仿真通过不等于实机几何或任务通过 |
| ACT | 根据观测预测七轴与夹爪的动作块 | 加入ACT类或加载checkpoint不等于学会泛化 |
| ZED | 提供当前RGB、深度、置信度和设备时间 | 画面稳定不等于独立空间精度合格 |
| YOLO及轮廓识别 | 杯子身份、候选范围、蓝卡和场景核对 | 检测成功不等于ACT动作成功 |
| MoveIt/几何检查 | 教师规划，或对ACT目标做路径有效性检查 | 教师规划不能改称ACT推理输出 |
| ROS控制器和CAN驱动 | 传递合法目标、接收反馈、报告执行情况 | action服务成功不等于实体发生了预期运动 |
| RViz/MuJoCo展示窗口 | 可视化和人工检查 | 动画成功不等于真实硬件成功 |

## 四 硬件 环境 坐标与模型接口

### 4.1 已使用的系统

主要设备是NERO七轴机械臂、AGX夹爪、固定安装的ZED2i。CAN接口为can0，历史现场配置为1 Mbps；ROS使用Jazzy。离线完整仿真记录使用Python 3.12、MuJoCo 3.15.0、PyTorch 2.5.1+cu121和RTX4090，渲染使用EGL。不同目录是隔离实验快照，不代表所有入口都可以互换执行。[S02] [S08]

### 4.2 8维 9维 15维及短历史

| 版本 | 数值输入 | 图像及输出 |
|---|---|---|
| 早期8维 | 七轴实测关节和一维夹爪总开口 | RGB；动作含七轴和夹爪 |
| 9维上下文 | 8维实测状态，加上一条已提交夹爪目标与当前开口的差 | 增加因果命令上下文，减少静止接触歧义 |
| 当前15维 | 上述9维，加杯底相对TCP三维、蓝卡相对TCP三维 | RGB与数值位置共同输入，输出20×8 |
| 短历史对照 | 每帧仍15维，另输入最近5次有效数值观测及年龄/有效性 | 当前RGB只编码一次，不是5张历史RGB全部输入 |

当前位置特征的定义是：

```text
visual_relative = [cup_bottom_base - tcp_base,
                   target_base     - tcp_base]
```

这些特征来自图像估计和机器人FK，不在正常策略中直接填仿真物体真值。仿真真值另用于任务评分、接触检查及明确标记的离线诊断。物理状态仍为8维，15维是网络的数值输入维度。[S27] [S51]

### 4.3 动作到底是绝对目标还是增量

硬件边界采用：

```text
[J1,J2,J3,J4,J5,J6,J7,gripper_total_width]
 七轴使用rad                         夹爪使用m
```

动作是绝对关节目标和绝对夹爪总开口，执行端不能再把它们当成增量叠加。反馈残差、tanh读出和后来的夹爪命令增量头是模型内部的表示；经过读出后仍必须转换成上述绝对目标。

“上一夹爪目标”必须是曝光前已经提交并可核对的命令，不能用未来动作或当前实测开口冒充命令历史。最新实测99.42毫米开口超过ACT合法目标上限95毫米，因此不能静默裁成95毫米并声称历史正确。[S41] [S46]

### 4.4 相机方向与仿真视角

ZED倒装后图像按180°约定转正；RGB/BGR显式转换。内参属于原始左目光学坐标，旋转后的像素要按对应映射反算，不能只转图像而继续直接套原像素坐标。

仿真图形窗口使用自由观察相机，可以拖动、旋转和缩放；当前ACT训练及评估使用固定的`calibrated_nero_camera`，按相机内参、外参和图像方向构造。训练RGB渲染为320×180，再按具体模型配置预处理。固定相机的目标是匹配真实视角，但物体材质、杯把、背景、遮挡、噪声和投影精度并未因此自动一致。[S27] [S52]

### 4.5 时间与速度的区别

仿真控制周期50毫秒、积分步长2毫秒，不等于实机严格连续20Hz。还要计入收帧、反馈、推理、碰撞检查、记录、发送和确认时间。

至少要区分设备曝光时间、主机接收时间、推理时间、ROS目标时间、SDK发送完成时间和反馈时间。低推理耗时不代表整条指令新鲜；记录器20Hz采样也不代表机械臂连续20Hz执行。

## 五 10月14日至16日 从环境和链路核对到完整教师抓放

### 5.1 旧模型与现场起点不匹配

V9只读shadow能够加载模型并输出有限值，但若干关节和目标XY偏离示教范围。另一份原始动作检查中，第十步J3目标与实测状态差约118.88°，夹爪预测约1.49毫米。处理方法是保存真实起点和场景，重建数据、归一化及模型，不放宽门槛直接下发旧输出。[S03] [S04]

### 5.2 先核实真正的硬件反馈

MoveIt和GenericSystem可以在实体不动时报告轨迹完成，因此先核对真实反馈发布者，并用SDK只接收观察器交叉验证。J1增加0.005 rad、至少4秒的小幅试验是控制链路测试，而不是最终抓放方案。[S05]

后续完成高位准备和空中序列，再执行原幅度空载参考：1229点，名义61.45秒；实体最大行程约J2 63.591°、J4 47.876°、J7 77.959°。这轮使用示教轨迹而非在线ACT预测，且杯子已移开，不能算抓杯成功。[S01] [S06]

### 5.3 名义TCP与教师抓放

历史桌面Z有0、−10、−13毫米等来源；TCP也有135毫米近似值。旧TCP在模型碰撞检查中不通过后，用户接受模型名义TCP `[152,0,−23.5]`毫米。它是link7局部偏移，不是新独立实测结果；不能把安装板链接偏移重复相加。[S01] [S07]

教师流程最终按高位接近、张爪、低速下降、GRASP、抬升、搬运、下降、RELEASE和垂直退出分段完成。视觉曾受YOLO框下缘漂移影响，改用杯子身份与黄色轮廓共同确定边缘；蓝卡使用唯一蓝色凸四边形。旧位置偏差约6.06毫米触发停止，修正后26帧核对通过，没有通过放宽原5毫米变化门槛接续。[S01]

10月16日的监督MoveIt抓放有成功验收；它说明当时的场景和教师路线能够完成物理任务。验收明确写`act_policy_used_for_this_grasp=false`，并没有把记录独立批准为训练集。[S07]

## 六 10月17日 完整ACT仿真与第一次在线迁移

### 6.1 完整任务数据是怎样生成的

物理教师用IK和笛卡尔插值产生目标，由带延迟的伺服模型执行；杯子靠双指接触和摩擦搬运，不通过重置杯位或加约束把杯子粘到夹爪上。每条示教要通过完整物理任务、动作前缀合同和同状态精确重放检查。[S08]

run11使用43条资料：29训练、12验证、2开发诊断；其中完整示教和局部恢复分别统计。模型用90×160 RGB与8维状态，预测20×8，最多执行前10点再重新观察。该历史版本明确采用prior-only行为克隆、KL=0，不是已经训练CVAE后验的标准配置。[S00] [S08]

完整任务评价要求有夹持下抬升、至少100毫米搬运、目标附近承托释放、退出、稳定放置，并且无提前释放、意外接触和合同失败。run11严格14项为6/14；固定名义场景可以完整成功，不能说严格鲁棒性通过。

### 6.2 第一次在线ACT真机接近

真实RGB和反馈进入冻结ACT，实际完成58块、580点；第59块因控制器确认未在原45毫秒期限内完成而停止。实体J2变化约52.62°、J7约61.72°，说明发生了大幅实际运动。580点名义29秒，实测执行约33.27秒；尚未GRASP，没有抓杯搬运。[S09]

### 6.3 到抓取位却不闭爪

后续在线尝试到达杯旁，现场给出GRASP；255个保持块中，ACT仍预测约92.74～95毫米张开目标，实测约94.875毫米、力约0.035N，没有稳定夹持。程序停止，没有用手写闭爪命令替代ACT成功。[S11]

这说明同一模型在名义仿真成功、当前真实前缀合法，仍不足以证明真实接触阶段成功。后续工作由此转向抓取状态覆盖、夹爪学习、因果上下文及视觉分布。

## 十一 10月21日 冻结范围 接近保持和优化控制

### 11.1 只训输出层仍可能改变接近

受限微调从共同基线开始，仅训练七轴输出行与非线性夹爪头共6个张量，其余208个摘要不变。零更新基线能够进入GRASP，但后续桌面保护失败；训练后2710点仍没有GRASP并触发关节限位。这说明共享输出层足以改变整条接近轨迹，不需要视觉骨干变化才能退化。[S38]

### 11.2 接入保持损失也需要检验

保存原基线423次抓前观测和20点读出，每步增加8个参考，约束执行前2点。启动前修正GPU渲染、限幅前后比较、channels-last图像布局、批量与单帧前向差及来源绑定；423个参考在更新前输出差0。[S39]

训练后夹爪漂移减小，但七轴RMS漂移从约0.247升到0.961毫弧度，最大从0.942升到3.259毫弧度；六项5/6降到4/6，高位仍碰杯。因此“加了保持损失”不能直接写成“保持改善”。

### 11.3 梯度尺度与学习率

后续发现保持损失梯度范数约1.26万～27.44万，而普通监督约10；全局裁剪会连同夹爪学习一起压缩。另确认4组完全相同RGB+15维却有不同前两点标签，过滤较早静止等待视图，原HDF不改。

七轴学习率固定1e−6和线性衰减到1e−7两组各1000更新，七轴保持RMS约0.007789/0.004840毫弧度，均通过原保持门槛；六项都仍4/6，未完成所需夹持差。相对于更早版本，这里还包含标签过滤，不能把全部变化都归为学习率。[S40]

### 11.4 根因复核得到的数值证据

只读复核重建8个失败查询，预测最大差0。名义失败输入与训练数据可以完全或近乎完全一致，因此这部分错误在同一仿真域内已经存在，不能归因于真实画面渲染差异。[S41]

已确认的问题包括：

- 完整示教夹爪每点0.4毫米，恢复示教每点0.2毫米，输入却没有显式速度尺度条件。
- 同一holding窗口，前2点与后18点夹爪梯度余弦约−0.96至−0.97，说明动作块监督在这个输入上互相抵消。
- 已夹持输入曝光120次仍预测松开，故“只要多采同样的数据”不足以解释问题。
- 接触边界样本曝光薄，但也不能把所有错误统一归为采样数量。
- 权重、统计、源码和冻结范围一致，没有发现错误checkpoint或权重文件损坏。

## 十三 控制器状态 反馈来源与ROS CAN启停

### 13.1 为什么出现arm_status等问题

控制器状态、独立错误码、运动状态和电机使能不是同一个量。历史状态2由控制器真实上报，不能把软件变量改成0来当作恢复。ACT的15维数值输入不包含`arm_status`，所以可以只读分析策略预测，同时仍让运动入口保留状态检查。

用户选择过“先单独分析策略输出，保留运动保护”。后来独立受限演示入口对状态0/2有明确条件允许，并同时要求错误码0、反馈新鲜、静止、实际使能、领先量和碰撞检查通过。它不是全局取消状态保护，更不代表状态2等于正常0。SDK的reset还可能实际发送急停恢复指令，不能当成普通无解状态的专用清零命令。[S53] [S49]

### 13.2 反馈为什么必须交叉核对

用户多次恢复起点或调整模式，但有时只恢复了杯位/夹爪，没有把整臂回到原姿态。另一些时刻ROS可能来自虚拟系统或其他域。处理方法是核对发布者、真实SDK七轴和夹爪反馈、运动状态及起点差值，避免把意图当成已发生的物理状态。

“姿态不同”不能自动归咎于策略。最近演示发送器停止后，后验姿态再次改变；用户确认手工移动或切换过模式，因此该变化另记为现场操作后的状态，不归入原ACT轨迹。稍后全局CAN多1包的具体发送者没有被独立确认，不能仅凭这1包猜测控制者。[S49]

### 13.3 启停服务与授权的范围

对话中先后要求关闭、重新打开ROS和CAN。每次以当时明确要求为准，启动接收服务、启用运动发送、使能、失能和模式切换分别记录。只读观察器需要封锁SDK发送路径；ROS或相机启动本身不能计为一次任务动作。

本报告整理期间只读取文件，没有重新打开相机、启动运动或切换控制模式。历史PID和CAN计数是对应日志时刻的快照，不用它们保证报告阅读时的实时硬件状态。

## 十八 观测误差 策略误差与RGB-D候选

### 18.1 杯位准确一点是否就能全部解决

固定1a28、RGB、反馈、蓝卡与全部保护，只把杯位三项替换为同曝光物理真值，五个诊断场景完整结果0/5。正常9005六类数组先完全复现，再执行对照；诊断真值没有进入正常训练或真机入口。[S48]

这证明“只修这三项杯位特征”不足以救回该模型，不能证明视觉不重要，也不能排除旧策略和有偏观测已经耦合。还需处理蓝卡、接触状态和闭环恢复。

### 18.2 已证实的遮挡定位误差

9005夹持遮挡后，图像估计杯底比实际高约8.06毫米，总位置误差约11.89毫米，而包围框拟合RMSE仅0.181像素。小像素残差不代表真实三维位置正确。

原分辨率RGB候选的验证帧21/22有效，但只有9张在2毫米以内，最大3.27毫米，未达到全组精度要求。没有因为单元测试通过就部署该观察器。[S47] [S48]

### 18.3 RGB-D做了什么

利用同曝光1280×720 RGB、相机Z深度或SDK XYZ、置信度，拟合空心杯首个可见表面；仅匹配最近杯壁会混淆不可见内壁，首版遮挡误差约2.91毫米，后用射线首交点约束修正。

独立审查发现有符号残差会漏检单侧异常，v2改为绝对射线残差。理想深度开发14/14、留出21/22；预设0.35毫米噪声及15%随机缺失压力下，开发仅12/14有效，85.7%低于90%门槛。更严格版本推翻了v1“机制整体通过”的早期结论。[S48]

这里的0.35毫米噪声和15%缺失是合成压力工况，尚未证明它们与现场相机的真实噪声分布一致，不能据此直接计算现场成功率。

95分位耗时约430～891毫秒，尚不满足实时闭环。当前保存的3张实景帧又在蓝卡轴对齐模型处被拒绝，所以不能用“相机有深度”替代“当前15维视觉输入已就绪”。

### 18.4 深度稳定性与绝对精度

ZED2i、SDK5.4.1、HD720/30Hz、NEURAL_LIGHT采过20个新曝光。旧静止判据只检查ROI中心，可能漏掉轴向运动；v2加入共享XYZ时间变化。原20帧只保存了0/9/19三份原始数组，对这3份复算Z标准差95分位约0.229毫米。

0.229毫米是特定静止启发式下的重复性，不是手眼、TCP、杯底绝对精度，也不能声称独立重算了全部20帧。RGB像素转180°，SDK XYZ仍保留原光学向量方向，不能再重复翻轴。[S48]

### 19.1 命令时效是什么意思

“时效”是指准备发送时，距离该条ROS目标产生已经过去多久。本次上限250毫秒，拒绝点实际381.65毫秒，因此出现`stale_command`。

它不是现场授权30分钟有效期，也不是轨迹单点50毫秒、模型推理耗时或3秒到位超时。它约束的是该条指令的新鲜程度，防止基于旧状态生成的动作继续发送。

发送前记录与复读反馈窗口约377.97毫秒，包含日志、读取和调度；离线同报告JSON序列化约19～30毫秒，不能断言全部378毫秒就是写日志造成。后续要分段计时定位阻塞，不能简单改大250毫秒或重写时间戳来绕过。[S49]

### 19.2 演示后状态变化怎样解释

首次后验状态0、错误0、静止，姿态符合停点。后来姿态离开停点并出现状态6，SDK定义为关节制动未释放；用户随后确认手工移动或切过模式。该变化另记，不回写成ACT继续运动。额外1包CAN的具体来源仍未独立归属。

## 二十二 当前泛化能力不足的原因

### 22.1 有位置扰动数据不等于覆盖了目标工作区

项目早期确实生成过±30毫米位置及起点扰动，不能说从未做位置随机化。但旧相机数据、新外参、不同TCP假设、不同模型和协议属于不同分布；它们不能简单累加成“当前模型已经见过足够多新场景”。

新相机阶段主要完整位置覆盖是中心和四个轴向±15毫米点，目的首先是恢复当前场景。二维斜向组合、起点变化、杯子朝向、蓝卡朝向和遮挡组合仍覆盖不足。后续缩小数据域继续微调，还可能遗忘原有恢复行为。

### 22.2 输入位置不等于动作真正依赖位置

15维已经有相对TCP坐标，但模型仍可主要依赖关节姿态或图像中的阶段线索预测一条常见轨迹。同一姿态不同杯位的对照已经测出某些位置响应远小于教师。训练误差较小，并不证明策略学会了正确条件依赖。

输出仍为绝对关节目标，目标移动不是给七轴统一加同一个位移。末端位置、姿态和整臂关节冗余需要共同调整；相对坐标只是提供信息，不自动赋予位置等变性。

### 22.3 感知误差与物体变化处于同一量级

当物体只移动一厘米，而遮挡下杯底误差已达到8毫米，模型可能得到错误的对中/抓高条件。相机视角投影匹配也不能消除TCP、杯柄、杯口和桌面模型误差。

### 22.4 理想轨迹与策略访问状态不同

教师在理想对中状态知道下一步，策略自己的前序误差会把系统带到训练覆盖之外。后续又遇到新遮挡、新夹持差和新接触，误差可能继续传播。补失败状态的专家纠正，比只重复理想成功轨迹更直接；这与模仿学习中访问状态分布变化的经典问题一致，但本项目仍需用具体对照验证。[DAgger原论文](https://arxiv.org/abs/1011.0686)

### 22.5 失败还包含保护与观察器的拒绝

位置改变后失败可能是策略走偏，也可能是蓝卡定位拒绝，或附着支撑状态使原保护拒绝。不能把这些都记成“ACT完全没有泛化”，更不能靠忽略观察器/保护来声称泛化实现。

最终目标应是：在预先明确、已验证的工作区内，当前真实图像和反馈直接进入ACT，执行短段再观察，完整抓放在未训练位置上通过。仿真用于训练、诊断和版本验收；每次现场执行不再为该杯位重新生成整条任务参考。

## 二十三 真机示教微调能改善什么 不能替代什么

### 23.1 有望改善的部分

- 真实杯子材质、杯把、阴影、显示器和夹爪遮挡等图像分布。
- 真实伺服的滞后、关节反馈与命令之间的差别。
- 实际杯壁接触、夹爪开度与命令差、抓稳到起抬、落桌到释放的过渡。
- 真实不同杯位下的接近路径与整臂协同，而不只模仿同一条仿真参考。
- 策略有偏时，由操作者或教师提供正确恢复后续，补足理想轨迹之外的状态。

这些是采用真机示教的理由，不是采集后保证成功的承诺。

### 23.2 真机示教不会自动修好的部分

动作标签定义错误、关节顺序或单位错误、相机时间配对错误、未来命令泄漏、运行保护的状态机缺陷，不会因为数据是真实采集就消失。

如果15维前端在杯被遮挡时仍输出错位或拒绝，新RGB示教也不能直接把缺失几何填出来。应该保留原始RGB-D，统一训练与推理前端；若要改成另一种观测结构，需要另做明确的模型/接口方案，而不是暗中补零或填旧杯位。

真机示教可以学习实际运动，但不能把未验证的TCP/相机几何写成已测量。现有新手眼及历史样本优先复用；如后续数据审计定位到具体缺项，只补缺项，不重复整套人工测量。

## 二十六 真机示教采集的最小补充链路

这一节是后续方案，尚未启动新采集、训练或硬件控制。优先用用户已有资料，只在确实缺少字段时补录。

### 26.1 优先复用现有控制者

项目存在Leader记录器和监督教师记录骨架，未发现一条已核实可直接用于本次全部功能的独立通用teleop入口。应先确认已有控制器是否能导出真正目标/回执；如果可以，让现有控制者完成动作，记录器只接收，不另造第二个CAN发送者。[S65]

现有`record_episode.py`可能进入Leader/Follower并操作夹爪，它不是只读命令，不能为了看看界面就自动运行。用户本次提供的是数据位置，并不等于授权切模式或执行动作。

如果由手工拖动产生示教而没有实际电机目标流，则必须选择清楚的未来状态模仿语义；它与当前命令预测模式不同，需要专门转换和对照。不要继续把同帧qpos直接称为目标命令。

### 26.2 记录钩子应放在真正发送边界

保存教师原目标、保护后提交目标、SDK调用起止、发送端提交、控制器接收或接受ACK，以及实际执行反馈和拒绝原因。每个确认都要注明来自哪一层；SDK函数返回、发送端提交或控制器ACK均不能单独证明物理动作已经执行完成。相机线程复制qpos不能取代动作记录。被保护拒绝而未发送的目标要单独标明，不能让训练以为机器人已经执行。

一次完整episode至少应包含以下信息，具体文件布局可沿用现有HDF5，不要求另造格式。

```text

  robot_id camera_serial calibration_hash tcp_profile observer_hash
  demonstration_mode action_semantics session_id position_group
  task_success operator_review initial_command_receipt

  raw_rgb raw_depth_or_xyz confidence intrinsics rotation_convention
```

### 26.3 时间配对原则

先建立并保留设备时钟到主机monotonic的映射及误差，再按曝光时刻匹配反馈；若只能按接收时间配对，就明确标为接收配对，不能伪装曝光同步。

上一夹爪目标选择曝光前已确认的最后命令。未来监督目标应发生在这次观测之后；动作与反馈错一帧、把尚未提交目标当过去历史，会直接改变闭合进度的含义。

ZED30Hz、反馈更高频、动作20Hz可以并存。保存原始异步流再派生训练视图，比把所有流强行写成“同一时间戳”更可审计。训练时执行前2点的标签间隔应匹配未来部署的实际节拍。

### 26.4 视觉一致性原则

当前RGB-D候选没有整体通过且延迟偏高，因此不直接作为采集时唯一在线依赖。先完整保留RGB-D原始流，离线生成特征和质量标记；训练和部署最终要使用同一已验证前端。

对只有RGB的旧记录，只有所选前端存在已验证的RGB-only路径时，才可离线派生对应特征；当前需要同曝光XYZ和置信度的RGB-D候选不能直接处理这些旧RGB记录，也不能补造缺失深度。对受遮挡阶段应真实保留无效情况，用于确定需要前端修正、其他可观测线索或额外数据的具体位置。

## 二十七 建议的多位置真机微调试验

以下数量、比例和门槛是首轮实验建议，不是已经执行的工作，也不是保证泛化的最少数据定理。

### 27.1 第一阶段 优先审计与复用已有数据

1. 已定位79份旧真实教师资料并生成上节审计清单；接着核对逐条完整任务和不同位置的分组。
2. 用少量样例同时绘制qpos、提交目标、夹爪反馈/命令、图像时间，检查因果关系和停滞标签。
3. 核对新旧相机标定及帧方向；能重新派生特征的重算，不能的保留原域标签。
4. 先建立不更新权重的基线：同一真实记录输入的旧模型动作、位置敏感性、闭合推进、起抬与释放误差。
5. 数据不符合当前动作语义时，先完成转换方案或补日志，再训练。

### 27.2 第二阶段 数据覆盖建议

优先在已有净空和可达工作区内选位置，不先承诺任意桌面位置。一个可操作的首轮分组是：

| 用途 | 建议配置 | 要点 |
|---|---|---|
| 训练完整示教 | 8个杯位，每位2次，共16次 | 覆盖中心、轴向和斜向，不全部是一条轨迹平移 |
| 开发验证 | 4个不同杯位，每位2次，共8次 | 整个位置/episode留出，不随机拆帧 |
| 冻结后的独立测试 | 6个未用于修复的位置，每位2次，共12次 | 不看结果后再把同一测试集称独立；若参与修复就转为开发 |
| 恢复片段 | 10～20段 | 安全的横向偏差、夹稳起抬、承托释放和退出；每段有正确后续 |

合计建议36次完整任务及恢复片段；如果现有文件已覆盖这些条件，可直接抵扣，不要求重新采同样数量。若现场成本较高，可先用少量高质量记录验证“确实能学到所缺依赖”，再决定扩数据；不把重复帧数当成独立示教数量。

第一轮可保持蓝卡位置固定、重点改变杯位，先验收杯位泛化；之后另做蓝卡位置/朝向和机械臂起点变化，避免同时变化过多而无法定位原因。杯把朝向和主要遮挡要有记录，不假装圆柱几何覆盖所有实物外观。

### 27.3 第三阶段 低预算微调与行为保持

初始化优先选择与当前相机和接口一致、仍保留成功行为的候选，不能继续从已拒绝的eec模型盲目加步。

先冻结视觉骨干、CVAE和大部分策略，用小预算检查真实数据上的闭合推进、位置响应、起抬与释放是否可学习。输出层/夹爪头优先；如果同姿态不同杯位仍完全学不会，再明确设计有限输入投影或解码层解冻对照，不直接一次开放几十个共享张量。

不能承诺“只训头就一定好”：历史受限头部也曾失败。选择参数范围需要由当前真实数据的机制探针与完整回归决定。

混入当前相机下已有成功接近和完整后续行为作为保持，覆盖多个杯位及多个阶段；不只保中心96个前两点。若使用旧相机数据，应区分域并验证，不把旧世界坐标与新外参混合成无标记数据。

先做约200～500次更新的小预算机制试验，权重和效果单独记录；机制通过后再声明下一组训练预算。检查真实标签上的误差、因果夹爪命令推进、低位净空与位置响应，以及原完整成功场景是否保持。训练损失下降、单个输入拟合好，都不是扩大预算的充分理由。

### 27.4 第四阶段 完整评估与真机在线运行

评估必须覆盖抓取、离桌抬升、转运、目标承托、松爪、退出；任何一阶段停滞、拒绝、滑落或提前释放都计完整失败。开发与独立位置分别统计，失败仍保留在分母。

物理接触前先验证观察器、命令合同、时间、起点和所有实时保护。进入已明确工作区后，目标链路是：

```text
真实当前图像/反馈 → 同一前端15维观测 → ACT新动作块
          → 实时检查 → 执行短段 → 新观测 → ACT继续调整
```

验收期间不为每个杯位重生成完整仿真参考，也不用手写IK/闭爪接管后仍计ACT成功。仿真保留为版本测试和诊断工具，实时碰撞/接触检查继续存在。

首次可沿用已有关键接触确认，避免每个小角度都询问；这些是有人监督的可行性试验，不提前宣称无人自主部署。异常停止后不自动重试、回位、使能或切模式。

关于成功率，可以事先约定不少于20次不同位置完整试验、至少16次成功作为一个开发目标，但样本少时仍要报告逐位置结果和失败类型。具体阈值应与任务用途、当前几何和现场条件一起确定，不能为了让结果好看而在试验后修改。

| P1 保持 | 局部微调破坏已有完整接近或后续动作 | 多场景多阶段保持，限制更新范围，原成功案例不退化才考虑推广 |
| P1 时序 | 最近发送前382毫秒超过250毫秒 | 分段计时日志/反馈/调度与发送，保留过期拒绝和新鲜反馈，不刷新假时间戳 |
| P1 真机数据契约 | 旧标签与当前submitted目标不同，夹爪意图缺回执 | 接发送边界日志；不能从同帧qpos伪造已发命令 |

## 二十九 复盘后的方法调整

1. **先识别失败属于哪一层。** 没有真实运动、视觉无效、策略错误、接触状态、命令过期和标签错误，处理方式不同。
2. **先验证真实失败输入，再扩大训练。** 专家理想输入已正确时，应优先检查策略实际访问状态和前端，不能只重复理想示教。
3. **把每次训练的假设缩小。** 改采样、损失、学习率、冻结范围和前端同时发生时，整体改善或退化不能归给某一项。
4. **保持覆盖完整行为。** 接近首两点保持只是局部约束；完整抬升、转运、释放和退出也可能被共享权重改变。
5. **新增位置才是泛化测试。** 用过的失败案例进入修复后就是开发数据；相邻帧随机拆分也不是位置留出。
6. **复用现场资料，减少重复要求。** 检索标定、已录原图和真实命令，再指出确切缺项；不重复要求用户对同一个参考点测量。
7. **把进程完成与任务完成分开。** error=null、complete=true、测试全绿、模型能加载、控制器ACK，都不能单独证明杯子放到了蓝卡。
8. **数据真实性与语义一起审计。** 真机数据比仿真更接近现场，但错误标签或错配时间也会让策略学错。

当前最值得继续的路线是：**审计用户已有真机示教 → 补足真正命令和因果时序 → 统一已验证视觉输入 → 小预算真实数据微调与完整行为保持 → 未训练位置在线完整抓放验收。** 这条路线正面针对当前泛化与迁移缺口，而不是继续要求每次摆回唯一杯位。
