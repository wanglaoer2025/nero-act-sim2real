# ACT run15失败排查与视觉训练修复

本目录独立保留修复源码；run14、run15的原源码、数据、权重、失败和训练证明不修改。本轮只做离线仿真与训练。

确认的代码缺陷：`FullTaskPolicy`无条件冻结全部视觉骨干，忽略`freeze_backbone=False`。run14和run15的100个骨干权重/缓冲张量逐值一致。在480个验证窗口中，动作方向在下降/搬运/放置等阶段拟合较好，但闭环仍会在抓稳后停滞、提前松爪或发生接触异常。不能用低验证损失替代任务成功。

已排除的假设：抽查480个验证窗口没有教师前10点超出有界输出可表达范围；静止预测基线显著差于已训练模型，不能直接说模型只学会“复制当前位置”。80个与新随机模型相同的骨干张量为固定归一化缓冲，20个卷积参数均不同，不能据此宣称当前全部视觉权重就是seed42随机初始化。

修复：尊重冻结开关，原默认行为保留；新增训练参数`--train-visual-backbone`。回归测试验证开启后视觉梯度非零、优化器实际更新卷积权重，同时冻结模式仍不更新。数据和执行保护不变。

受控run16与run15使用相同54条数据（40训练/14验证）、同一run14初始化、同一新统计、seed42、学习率和20轮，唯一区别为允许视觉骨干参与学习；新16个独立工况在训练前声明并绑定。同样的旧16项作开发回归，新16项只在冻结后评估。不将新测试与旧测试当作逐例相同的对照。

这是对明确代码缺陷的修复及因果检验；不能预先承诺它能单独解决所有失败。要以新冻结模型完整抓放结果判断，若仍失败，继续根据实际偏差定位，不削弱接触/地板/动作合同。

证据：`evidence/run15_training_diagnosis.json`、`evidence/visual_learning_red.log`、`evidence/visual_learning_green.log`、`evidence/full_suite_visual_fix.log`。动态训练/评估状态将写入`evidence/run16_pipeline_status.json`。

因果解释的边界：run15原配置本身为`freeze_backbone=true`，所以其视觉不更新与原配置一致；“关闭冻结仍无效”是确实存在的代码缺陷，但不能单凭这一点断言它就是run15全部失败的原因。run16才用于检验启用视觉学习能否改善闭环。

进一步检查发现：48条完整教师在闭爪末尾的姿态误差仅0.00554～0.00610度；run15名义闭爪许可时已偏0.826度，停滞末尾1.995度。高位起点±3度不能替代接触阶段的扰动覆盖，闭环累积误差后的状态与完美示教不同。数据见`evidence/run15_contact_pose_diagnosis.json`。从名义停滞快照进行的专家后续动作仅作诊断，不计入run16训练或ACT成功。

run16正式训练已运行；第1轮实际checkpoint的20/20个卷积层权重均变化，最大参数变化0.001681，见`evidence/run16_actual_visual_update_audit.json`。目前只证明视觉学习开关已修复，完整任务结论等待冻结评估。

后续发现更直接的关键输入采样缺口，run16已在14/20轮主动停止并保留全部文件，不具备导出证明。当前正式修复移至[关键输入修复工程](../nero_act_transition_fix_20261018/README.md)，同时修正关键帧输入和RGB时序；不是run16已完成或通过。
