# Nero 关节响应复测 v2

本包修复旧0.5秒测试的验收漏洞。原包、源码和诊断证据保持原样。不加载v9，不操作相机或夹爪，不自动移动到模型起始姿态，不新增物理测量。

## 现场命令

复制整个包到4090，使用原有支持numpy与pyAgxArm的环境：

```bash
tar -xzf nero_response_probe_v2_20261014.tar.gz
cd nero_response_probe_v2_20261014
python run_short_test.py --dry-run --output logs/probe_001
python run_short_test.py --execute --output logs/probe_001
```

dry-run完全离线，不创建输出目录、不导入SDK；执行输出目录必须不存在。默认J1，可用 --joint-index 0..6 选择扫掠安全的关节。

停止ROS CAN驱动及其他控制程序，确认SDK独占CAN；停止驱动/切换控制时扶稳机械臂。空夹爪悬空，清理扫掠范围，准备实体急停。提示后输入 RESPONSE。连接会使能并进入Follower，保留V120 SDK设计，没有改用normal_mode。

## 方案与判据

固定正向偏移0.005rad（约0.286度），控制器速度5%，名义20Hz。1秒余弦缓升，2秒保持偏移目标并观察。保持阶段最后5次反馈须全部到达目标：七关节最大误差不超过0.001rad，测试轴正向进展至少0.004rad。通过后才开始1秒缓慢回位及2秒观察。回位最后5次七关节误差也须不超过0.001rad。总约6秒目标发送，连接和使能另计。

这些是本轮小幅诊断判据，不是已验证的机器人性能指标。低速或延迟导致未满足时保存失败证据，不能自动放宽或唯一归因。

每次读数要求SDK关节与控制器状态时间戳分别严格推进，150ms未更新即失败；运动前要求至少两次更新。时间戳只作推进比较，不假定其与主机同一时钟；这不能证明全部关节硬件同步或传感器绝对年龄。状态须为CAN/MOVE_J，arm_status及err_code为0。缺失字段或时间戳不支持时失败，不静默降级。

未跟随时不会自动发送起点，普通失败尝试以新鲜反馈保持当前位置；反馈超时、严重故障或中断尝试电子急停。退出不主动失能，速度5%不自动恢复。回位本身会运动。程序未退出前不要重启ROS驱动。

## 日志与限制

trace.json保存缓升、保持、回位阶段的目标、发送记录、反馈、SDK时间戳、控制器状态和主机时间。can_frames.jsonl从连接SDK前开始被动接收同期CAN帧，记录本地TX loopback标记；观察者不发送帧。本地TX回显不能证明控制器接受，需结合RX反馈和状态分析。未订阅CAN错误帧，文件不替代总线健康诊断。

report.json保存跟随/回位判据、错误、停止动作；失败返回非零，始终不表示v9迁移验收通过。带回整个输出目录及终端输出。即使退出0，也需核对原始轨迹与CAN证据。

已完成离线验证：静止但新鲜反馈失败、缓存关节/状态反馈失败、控制器故障阻止发送、0.8秒延迟在保持窗口内通过、回位失败不能通过。没有追加真机运动。
