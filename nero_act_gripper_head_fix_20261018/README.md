# ACT 夹爪输出行微调与机械臂权重隔离

状态：146项检查通过；run23三轮训练和冻结评估已结束。原场景0/1，验证42为1/1；原场景尚未修复，未连接真机。

## 为什么再隔离参数

run21的ACT机械臂能到原抓取位，但夹爪预测96.5～98.4毫米，经95毫米限幅后闭爪监督梯度为0。run22用限幅前零潜变量夹爪监督修复了此机制，固定原输入已能预测90.2～94.6毫米；然而全网微调后最低接近高度变成58.19毫米，未进入原55±2毫米抓取确认区，完整任务仍失败。

本次从能到抓取位的run21初始化，复用run22同72条数据（51训练、21验证），仅更新动作头的夹爪第7行（从0计数）。视觉/机械臂及其他参数全部冻结，梯度掩码保护其他七行，AdamW衰减归0以避免零梯度参数仍变化。禁止此模式同时重置动作头或训练视觉骨干。

仍使用ACT每次从当前图像及9维因果观测输出20×8动作，未改成轨迹回放。CVAE后验权重来自已训练run21并保留；本阶段只适配夹爪输出行，KL0.001、零潜变量限幅前夹爪监督0.05保持。执行端所有限制与保护不变。

## 验证及边界

- 新单步优化测试在修改前失败，修改后证明只有夹爪行更新，其余权重、缓冲区和同输入七轴预测逐项相同。
- 13项专项测试及最终146项全套离线/物理检查通过。
- 独立审查无严重/重要问题；已将训练模式显式取自CLI，避免后续训练继承错误冻结范围。
- 训练3轮后，`evidence/audit_frozen_arm.py`必须核对每一个保存检查点与重配归一化的初始化：除夹爪行外所有值完全相同，才准导出并评估。
- 同输入输出一致不保证改变夹爪之后的新闭环观测相同，完整抓放仍必须实际验证；不能以冻结证明代替物理结果。

原场景在第1261步到达TCP高度54.868毫米，源位水平误差2.610毫米、朝向误差3.449°；抓取高度±2毫米范围内共有17次查询，前10动作点全部预测95毫米全开。因此并非本次执行保护拦截了已产生的有效闭爪目标；策略继续下降到45毫米以下而停止。该段FK与MuJoCo独立核对误差小于1e−10米。

对同一真实失败输入的固定读出，限幅前预测从96.53～98.42毫米降到95.39～96.51毫米，监督损失0.2521降到0.1526，但限幅后仍全部95毫米。这证明训练有响应，尚不足以在该输入产生闭爪。不能仅因梯度、单元测试或单一场景成功就宣布修复。

两次冻结评估的模型、统计、配置及源文件哈希已重新核验。执行仍为在线图像/状态驱动ACT，无运行时教师、手工闭爪或约束绑定；模拟确认协议不是现场授权。最新完整结果见 [final_verification.json](evidence/final_verification.json)，固定输入读出见 [fixed_grasp_readout_comparison.json](evidence/fixed_grasp_readout_comparison.json)。

用户批准CVAE调整后的三种尝试（恢复CVAE、全网增加限幅前闭爪监督、隔离夹爪输出行）均未使原场景成功。按调试流程，在下一次实现前需讨论共享表征、闭爪过渡监督与输出分支的设计；当前证据不能断言ACT框架本身无法完成任务，也不能断言仅加训练轮数即可成功。未启动第四次修改。
